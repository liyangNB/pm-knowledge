# 假设台账（Hypothesis Ledger）

不记预测，就永远学不到东西，只会讲故事。

## 记录格式

| # | 功能 / 实验 | 假设 | 预测 | 实际 | 判定 | 学到的 |
|---|------------|------|------|------|------|--------|
| H-01 | | 如果我们做 X，用户会 Y | 指标 A：41%→30% | 36% | 部分成立 | |
| H-02 | | | | | 不成立 | |
| H-03 | | | | | 成立 | |

## 判定标准

| 判定 | 条件 | 下一步 |
|------|------|--------|
| 成立 | 达到目标值 90% 以上 | 加投入 / 扩范围 |
| 部分成立 | 达到 50–90% | 定位漏点，迭代一次，60 天后复看 |
| 不成立 | 低于 50% | 停投入，做 5 次访谈搞清原因 |
| 无信号 | 使用率接近 0 | **下线**。留着是负债 |

---

## 为什么"不成立"那一行最值钱

它告诉你对用户的理解哪里错了。而这个认知会复用到下一个功能上。**一个季度积累 5 条"不成立"，比 20 条"成立"更有价值。**

## 检查频率

- 每周：更新进行中实验的实际值
- 每月：把已结束的填完判定
- 每季度：找出 3 条最重要的"不成立"，看它们有没有共同模式
