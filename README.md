# 产品经理知识库

这不是一份"产品经理名词解释"。它是一套**能照着做决策的工作手册**——每个方法都附带判断标准、证据要求和常见错误。

## 三条核心信念

1. **功能是假设，不是承诺。** 上线只是实验开始，不是结论。
2. **说不比说是更需要勇气，也更值钱。** 每个"是"都是对其他事的"不"，把取舍摆到桌面上。
3. **对齐不等于同意。** 你不需要所有人同意，你需要所有人理解决策、逻辑和自己在其中的角色。

| 你的处境 | 从这里开始 |

| 刚转岗 / 刚开始学 | `01` → `02` → `04` → `06` |

## 学习路径

**4 周速成（有真实项目在手）**
- 第 1 周：`01` + `02`，对现有需求做一次证据审查，把没有证据的需求标出来（通常能砍掉 1/3）
- 第 2 周：`03` + `04`，用 RICE 重排一次 backlog，写一份完整 PRD 并找人挑刺
- 第 3 周：`05` + `06`，为一个功能定义 30/60/90 指标和回滚条件
- 第 4 周：`07`，把过去一个月的客服/评论做成一份带样本量和置信度的洞察报告

**8 周系统（无项目，纯学习）**
在上述基础上加：`08`（第 5 周）、`09`（第 6 周）、`10`（第 7 周）、`11` 自测 + 补齐短板（第 8 周）。

## 关于"证据"的约定

这套材料反复用"证据"这个词，这里给个统一口径，避免自欺：

| 等级 | 证据类型 | 能支撑的决策 |
|------|---------|-------------|
| A | 对照实验、带对照组的队列数据 | 上线 / 全量推广 |
| B | 行为数据（漏斗、留存、频次）+ n≥10 访谈 | 立项、投入 > 2 人月 |
| C | n=5~9 访谈、客服主题聚类、竞品压力 | 探索性投入、MVP |
| D | 单个客户诉求、老板直觉、行业传闻 | 只够进 backlog 排队 |

**规矩：C 级及以下证据不能支持超过 2 人月的投入。** 想投更多，先把证据升到 B。
